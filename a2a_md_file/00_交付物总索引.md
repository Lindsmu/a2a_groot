## 4. 最重要的结论

当前项目支持三条 action 生成路径：

1. `Gr00tN1d7`：原始高斯噪声到动作的 DiT/Transformer Action Head；
2. `Gr00tN1d7A2A` + `a2a_flow_backbone="mlp"`：论文核心的 512 维潜空间 A2A，默认后端；
3. `Gr00tN1d7A2A` + `a2a_flow_backbone="dit"`：新增时间序列 latent-token DiT 对照后端。

两种 A2A 都使用 Flow Matching。区别不是“是否使用 Flow Matching”，而是速度场网络处理的潜变量形状：

```text
A2A-MLP：z [B, 512]       -> 4-block AdaLN-MLP
A2A-DiT：z [B, 8, C]      -> N-block temporal AdaLN-DiT
```

两者推理都从真实历史动作/执行状态编码得到的 `z0` 出发，再积分到未来 latent；都不是从高斯噪声开始。

## 5. 不能忽略的数据前提

历史 continuous trajectory 和未来 continuous trajectory 必须处于相同物理动作空间：相同单位、坐标系、旋转表示、控制器定义和时间对齐。原始 LIBERO 的 absolute EEF state 与 OSC delta command 不满足这一条件，因此严格模式会拒绝直接训练。

当前实现已经完成通用 canonical 数据契约、导出、审计和统计流程，但没有替某个具体机器人自动实现 controller-aware canonicalizer 与 runtime inverse-controller。真实数据必须先完成这一步。
