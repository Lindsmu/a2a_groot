00001 | # GR00T 潜空间 A2A：MLP 与时间序列 DiT 对比实现
00002 | 
00003 | 本文说明仓库中新增的时间序列 latent-token DiT 后端，以及如何在不影响原有
00004 | 4-block AdaLN-MLP A2A 的前提下训练和对比两种 Action Head。
00005 | 
00006 | ## 1. 实现边界
00007 | 
00008 | 本次修改没有替换原有实现，也没有修改原始 `Gr00tN1d7`：
00009 | 
00010 | - `Gr00tN1d7`：原始 GR00T N1.7，保持不变；
00011 | - `Gr00tN1d7A2A + a2a_flow_backbone="mlp"`：原有论文核心迁移，仍是默认值；
00012 | - `Gr00tN1d7A2A + a2a_flow_backbone="dit"`：新增时间序列 token DiT 对照组。
00013 | 
00014 | 旧 A2A 配置没有 `a2a_flow_backbone` 时会采用默认值 `mlp`，原 MLP checkpoint
00015 | 的模块名和参数路径没有改变。MLP 与 DiT 的 action-head 图不同，因此代码会拒绝把
00016 | 完整 MLP A2A checkpoint 静默加载成 DiT，反方向也一样。做公平对比时，两组应从
00017 | 同一个原始 `Gr00tN1d7` base checkpoint 开始，或分别使用各自架构的 AE warmup
00018 | checkpoint。
00019 | 
00020 | DiT 是 GR00T 上的研究扩展，不是 A2A 论文已经报告的网络。论文核心对照仍是 MLP；
00021 | 选择 DiT 时必须显式关闭 `a2a_strict_paper_architecture`，避免把实验扩展误称为论文
00022 | 原始架构。
00023 | 
00024 | ## 2. 两条计算路径
00025 | 
00026 | ### 2.1 原有 MLP 路径
00027 | 
00028 | ```text
00029 | history [B,H,A] --共享3层Conv1d+时间池化--> z0 [B,512]
00030 | future  [B,H,A] --同一个编码器-----------> z1 [B,512]
00031 | 
00032 | z_tau [B,512] --4-block AdaLN-MLP, condition=VLM+tau--> velocity [B,512]
00033 | z1_hat [B,512] --4-block residual MLP decoder----------> action [B,H,A]
00034 | ```
00035 | 
00036 | ### 2.2 新增 DiT 路径
00037 | 
00038 | ```text
00039 | history [B,H,A] --共享3层Conv1d，不做时间池化--> z0 [B,H,C]
00040 | future  [B,H,A] --同一个编码器--------------> z1 [B,H,C]
00041 | 
00042 | z_tau [B,H,C]
00043 |   + relative-position embedding
00044 |   + real/padded-history validity embedding
00045 |   + VLM/tau AdaLN condition
00046 |         |
00047 |         v
00048 | N-block temporal DiT self-attention --> velocity [B,H,C]
00049 |         |
00050 | Euler integration
00051 |         v
00052 | z1_hat [B,H,C] --展平后4-block residual MLP decoder--> action [B,H,A]
00053 | ```
00054 | 
00055 | 其中：
00056 | 
00057 | - `B` 是 batch；
00058 | - `H` 默认是 8；
00059 | - `A` 是 padding 后动作维度；
00060 | - `C=a2a_dit_token_dim`，大模型默认配置为 256；
00061 | - 第 `i` 个 token 对应轨迹窗口中的第 `i` 个相对时间位置；
00062 | - 历史 `[-7,...,0]` 与未来 `[0,...,7]` 分别保持自身时间顺序，Flow 学习两段
00063 |   token 序列之间的整体传输，不假设第 `i` 对动作在物理上相等。
00064 | 
00065 | ## 3. 为什么不是把 512 维向量随便切成 8 份
00066 | 
00067 | 新编码器在最后一层 Conv1d 后保留真实时间轴，每个 token 都来自对应时间位置及其
00068 | 局部卷积感受野。它不是先得到一个 512 维全局向量再 reshape。这样 Attention 的
00069 | token 才有明确的轨迹时序含义。
00070 | 
00071 | 默认 DiT 配置 `H=8, C=256`，因此 token latent 总元素数是 2048；它是有意增大的
00072 | 模型容量对照。若要做“潜变量总元素数相同”的结构消融，可设置：
00073 | 
00074 | ```text
00075 | a2a_dit_token_dim = 64
00076 | 8 tokens x 64 = 512
00077 | ```
00078 | 
00079 | 因此建议同时报告两种 DiT：
00080 | 
00081 | 1. `DiT-512-budget`：8×64，用于尽量公平地比较 MLP 与 Attention；
00082 | 2. `DiT-large`：8×256、8层，用于评估扩大容量后的上限。
00083 | 
00084 | ## 4. DiT block 具体做什么
00085 | 
00086 | 每个 `AdaLNDiTBlock` 包含：
00087 | 
00088 | 1. 无 affine 的 LayerNorm；
00089 | 2. 多头时间自注意力；
00090 | 3. 残差连接；
00091 | 4. 第二个无 affine LayerNorm；
00092 | 5. GELU feed-forward MLP；
00093 | 6. 第二个残差连接。
00094 | 
00095 | 连续 Flow 时间 `tau` 先做正弦位置编码，再和 GR00T VLM 条件向量拼接。条件网络为
00096 | 每个 block 产生两组 `shift / scale / gate`，分别调制 Attention 和 MLP：
00097 | 
00098 | ```text
00099 | AdaLN(x) = LayerNorm(x) * (1 + scale) + shift
00100 | x_attn   = x + gate_attn * Attention(AdaLN_attn(x))
00101 | x_out    = x_attn + gate_mlp * MLP(AdaLN_mlp(x_attn))
00102 | ```
00103 | 
00104 | 这里的 Attention 只在动作 latent token 的时间轴上进行；VLM 条件通过 AdaLN 注入。
00105 | 它没有改动 GR00T VLM 主干，也没有把视觉 token 复制进动作序列。
00106 | 
00107 | 代码没有直接调用 `nn.MultiheadAttention`，而是显式实现 `QKV Linear -> MatMul ->
00108 | Softmax -> MatMul -> output Linear`。原因是当前仓库使用的传统 ONNX exporter 会把
00109 | `nn.MultiheadAttention` 融合成不受支持的 `_native_multi_head_attention`。显式实现
00110 | 在数学上等价，并已经通过 PyTorch/ONNX Runtime 数值一致性与动态 batch/视觉序列
00111 | 长度测试，也更容易被 TensorRT 识别为标准算子。
00112 | 
00113 | ## 5. Flow Matching 没有改变
00114 | 
00115 | 两种后端使用完全相同的 A2A 数学目标。共享编码器得到：
00116 | 
00117 | ```text
00118 | z0 = E(history)
00119 | z1 = E(future)
00120 | tau ~ Uniform(0, 1)
00121 | z_tau = (1 - tau) * z0 + tau * z1
00122 | target_velocity = z1 - z0
00123 | ```
00124 | 
00125 | DiT 只是把张量从 `[B,D]` 改为 `[B,H,C]`。`tau` 会广播为 `[B,1,1]`，FM loss
00126 | 仍然是预测速度与 `z1-z0` 的 MSE。AE、可微 Euler Integration Consistency、连续
00127 | 动作 L1 和 auxiliary 动作损失也全部保留。
00128 | 
00129 | 推理仍然从实际历史开始，而不是从高斯噪声开始：
00130 | 
00131 | ```text
00132 | z = E(history)
00133 | for each Euler step:
00134 |     z = z + dt * DiT(z, tau, VLM_condition, history_validity)
00135 | future_action = Decoder(z)
00136 | ```
00137 | 
00138 | ## 6. 冷启动 token 的处理
00139 | 
00140 | 刚开始不足 8 个真实历史点时，processor/policy 仍按既有规则产生数值补齐和
00141 | `history_action_mask`。Token encoder 会在输入适配前清零无效数值，并在每一层
00142 | 时间卷积后再次清零无效位置，防止补齐值通过卷积泄漏。
00143 | 
00144 | DiT 不能简单删除这些位置，因为 8 个未来动作位置仍都需要生成。因此实现使用：
00145 | 
00146 | - 位置嵌入：告诉模型这是第几个相对时间 token；
00147 | - 有效性嵌入：告诉模型该历史 token 是真实反馈还是 cold-start padding；
00148 | - 不使用会删除 query 的 padding 逻辑：无历史的位置仍可从 VLM 条件和真实 token
00149 |   生成未来表示。
00150 | 
00151 | 整个 episode 开始前仍必须调用 `policy.reset()`，且预测动作不能回填为 executed
00152 | history。

00154 | ## 7. 配置字段
00155 | 
00156 | | 字段 | 默认值 | 含义 |
00157 | |---|---:|---|
00158 | | `a2a_flow_backbone` | `mlp` | `mlp` 或 `dit` |
00159 | | `a2a_dit_token_dim` | 256 | 每个时间 token 的宽度 |
00160 | | `a2a_dit_num_layers` | 8 | DiT block 数量 |
00161 | | `a2a_dit_num_heads` | 8 | 每层注意力头数 |
00162 | | `a2a_dit_mlp_ratio` | 4 | DiT FFN 扩展比例 |
00163 | | `a2a_dit_dropout` | 0.0 | Attention/FFN dropout |
00164 | | `a2a_strict_paper_architecture` | true | 只允许论文核心 MLP；DiT 必须关闭 |
00165 | 
00166 | 约束：
00167 | 
00168 | - `token_dim` 必须能整除 `num_heads`；
00169 | - 所有维度、层数、head 数和 ratio 必须大于 0；
00170 | - dropout 必须在 `[0,1)`；
00171 | - DiT 要求 history/future horizon 相等；
00172 | - 完整 A2A resume 时，backend、token width、层数、head 数等必须与 checkpoint 一致。

00231 | ## 9. 公平对比要求
00232 | 
00233 | 以下项目必须保持一致：
00234 | 
00235 | - 原始 GR00T base checkpoint；
00236 | - 数据集划分、canonical stats 和 contract hash；
00237 | - VLM 冻结/解冻方式；
00238 | - optimizer、学习率、batch size、训练步数和图像增强；
00239 | - history noise、Euler 步数和随机种子集合；
00240 | - 在线 history buffer、控制频率和执行 action chunk 的方式。
00241 | 
00242 | 建议至少报告 3 个 seed，并记录：
00243 | 
00244 | - 闭环任务成功率；
00245 | - AE reconstruction L1；
00246 | - FM、IC latent、IC action loss；
00247 | - 物理单位动作误差、轨迹抖动和动作饱和率；
00248 | - action-head 参数量、峰值显存和延迟；
00249 | - 1、2、4、6 个 Euler step 的成功率/延迟折中。
00250 | 
00251 | 单元测试通过只能证明公式、shape、mask、梯度和接口正确，不能替代真实机器人或
00252 | 仿真闭环效果。更大的 DiT 也不能修复错误的物理动作语义；raw LIBERO 的 absolute
00253 | proprio 与 OSC delta command 不在同一连续空间，仍受原 A2A strict contract 门禁。

00269 | ## 11. 怎样判断该选哪个
00270 | 
00271 | 如果目标是复现论文核心结构或先取得稳定基线，使用 `mlp`。如果数据规模足够、动作
00272 | 跨时间关系复杂，并且可以接受额外显存与延迟，再比较 `dit`。最终选择应依据闭环成功率
00273 | 与实际部署预算，而不是只看 validation FM loss 或模型参数量。

00275 | ## 12. 已完成的验收范围
00276 | 
00277 | 实现写回时完成了以下检查：
00278 | 
00279 | - token encoder/decoder 的 shape、mask 隔离、反向梯度；
00280 | - 时间 Attention 的跨 token 信息传播；

00287 | - DiT ONNX checker、PyTorch/ORT 数值 oracle、动态 batch 和动态 VLM sequence；
00288 | - 原始 GR00T N1.7 Action Head、Processor 和模型 forward 回归。
00289 | 
00290 | 当前环境没有 CUDA/TensorRT，因此没有实际构建 DiT TensorRT engine，也没有真实
00291 | canonical 数据训练和闭环成功率。ONNX 图和 TensorRT metadata/路由已经接通，但部署
00292 | 机器上仍应执行 engine build、数值 verify 和实际延迟测试后再决定生产使用。
