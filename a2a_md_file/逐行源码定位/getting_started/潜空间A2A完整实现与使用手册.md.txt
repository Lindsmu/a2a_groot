00001 | # GR00T N1.7 潜空间 A2A：完整实现与使用手册
00002 | 
00003 | 本文是仓库中 `Gr00tN1d7A2A` 默认 MLP 后端的实现参考与操作手册，覆盖“实现了什么、每个模块如何工作、数据怎样准备、怎样训练/恢复/推理/部署、怎样验收，以及当前不能做什么”。快速操作可先看 `getting_started/latent_a2a.md`；需要理解或修改默认论文核心迁移时阅读本文。新增的时间序列 latent-token DiT 是并列实验后端，不改变本文所述默认行为，单独见 [`潜空间A2A_DiT对比实现与使用.md`](潜空间A2A_DiT对比实现与使用.md)。
00004 | 
00005 | ## 1. 最终实现结论
00006 | 
00007 | 这是一个建立在 GR00T N1.7 VLA 基础上的新模型变体，不是完全独立的新视觉语言模型，也不是在旧 DiT 中把 `randn` 简单换成历史动作。
00008 | 
00009 | - 保留：GR00T N1.7 的视觉语言主干、token 化、数据框架、训练框架、policy 接口和多 embodiment 基础设施。
00010 | - 替换：原始“高斯噪声 → 原始动作空间”的 DiT action head。
00011 | - 新增：历史 executed-proprio 窗口、共享轨迹自编码器、默认 512 维潜空间和 4-block AdaLN-MLP FlowNet、可选时间序列 DiT FlowNet、AE/IC 损失、有状态历史 buffer、canonical 数据契约和 A2A 专用 ONNX/TensorRT 路径。
00012 | - 不影响：原始模型类型仍为 `Gr00tN1d7`；A2A 使用独立 `model_type="Gr00tN1d7A2A"`，不会覆盖旧模型注册。
00013 | 
00014 | 实现的论文核心是：把最近执行历史编码成 `z0`，把未来动作编码成 `z1`，在共享 512 维潜空间学习从 `z0` 到 `z1` 的条件速度场。推理从 `z0` 开始，因此不再创建高斯动作初值。
00015 | 
00016 | ## 2. 论文方法与本项目实现的边界
00017 | 
00018 | ### 2.1 与论文一致的核心
00019 | 
00020 | 给定执行历史 `a_hist`、未来示范 `a_future` 和视觉语言条件 `c`：
00021 | 
00022 | ```text
00023 | z0 = E_a(a_hist)
00024 | z1 = E_a(a_future)              # 只在训练时需要
00025 | tau ~ Uniform(0, 1)
00026 | z_tau = (1-tau) z0 + tau z1
00027 | v_target = z1 - z0
00028 | v_pred = f_theta(z_tau, tau, c)
00029 | ```
00030 | 
00031 | 同一个 `ActionTrajectoryEncoder` 同时计算 `z0` 和 `z1`。三个论文损失被逐项实现：
00032 | 
00033 | ```text
00034 | L_FM = MSE(v_pred, z1-z0)
00035 | L_AE = L1(D_a(E_a(a_future)), a_future)
00036 | z1_hat = Euler(f_theta, z0, c)
00037 | L_IC = L1(z1_hat, z1) + 0.5 * L1(D_a(z1_hat), a_future)
00038 | L_total = 1.0*L_FM + 0.5*L_AE + 1.0*L_IC
00039 | ```
00040 | 
00041 | 严格连续动作时，上式就是实际总损失。默认 horizon 是历史 8 步、未来 8 步；latent 是 512 维；encoder 是 3 层 kernel-5 Conv1d；FlowNet 是 4 个 AdaLN-MLP residual block；decoder 是 4 个 residual MLP block。推理默认做 1 步显式 Euler，也支持 PyTorch 路径的多步对照。
00042 | 
00043 | ### 2.2 为 GR00T 增加的工程适配
00044 | 
00045 | 下列部分不是论文原网络的逐比特复刻：
00046 | 
00047 | - 论文的 ResNet18 + linear condition 被 GR00T VLM + 语言 token + `VLMConditionPooler` 替代。
00048 | - 论文实验写 `m=8` 帧视觉历史；迁移方案保留 GR00T 当前/原配置视觉 horizon，示例是单帧 `[0]`。
00049 | - 多 embodiment 输入/输出由 `CategorySpecificLinear/MLP` 适配。
00050 | - binary、categorical、不能与 proprio 可逆对应的 regression 通道进入 auxiliary head，不污染连续 A2A latent。
00051 | - canonical statistics、版本化控制器契约、cold start、checkpoint 迁移、ONNX/TensorRT 都是生产化补强。
00052 | 
00053 | 论文没有公开 encoder 中间通道宽度、MLP ratio、激活、归一化、time embedding 和 IC 训练积分步数。本仓库固定 `(128,256,512)`、ratio 4、SiLU/LayerNorm、FP32 sinusoidal time embedding 和 1 步 IC Euler；这些是可复现的仓库实现选择，不能声称是未公开作者代码的精确数值。
00054 | 
00055 | ### 2.3 尚未复现的论文效果
00056 | 
00057 | 单元测试只能证明算法和软件接口正确，不能等价为成功率复现。当前仓库没有随实现一起提供 canonical 机器人数据、训练完成的 A2A checkpoint、3-seed 闭环结果或真实端到端延迟。因此准确表述是：核心方法实现正确，真实任务效果待数据转换、训练和闭环实验验证。

00059 | ## 3. 完整张量流
00060 | 
00061 | 默认 `B` 为 batch，`H=F=8`，`D=max_action_dim`，`L=512`：
00062 | 
00063 | ```text
00064 | history_action_canonical [B,H,D] ─┐
00065 | history_action_mask      [B,H,D] ─┴─> shared E_a ─> z0 [B,L]
00066 | 
00067 | future_action_canonical  [B,F,D] ─┐
00068 | continuous_action_mask   [B,F,D] ─┴─> same E_a ─> z1 [B,L] (train only)
00069 | 
00070 | backbone_features [B,S,C] + attention/image masks
00071 |     └─> masked global/image/text pooling ─> c [B,L]
00072 | 
00073 | z_tau, tau, c ─> 4×AdaLN-MLP ─> latent velocity [B,L]
00074 | z0 ─> differentiable Euler ─> z1_hat [B,L]
00075 | z1_hat ─> 4×residual MLP decoder ─> continuous future [B,F,D]
00076 | c + z1_hat ─> auxiliary head ─> regression/binary/categorical future
00077 | mask merge ─> action_pred [B,F,D]
00078 | ```
00079 | 
00080 | mask 既决定哪些值进入 encoder/loss，也决定输出位置。模型逐样本检查至少存在一个 continuous 通道；history 和 future continuous support 必须完全一致；重叠 head mask、未覆盖有效位、padding 位上错误生成 mask、NaN/Inf 和错误 horizon 都会立即失败。

00123 | ## 5. 数据必须先满足什么
00124 | 
00125 | continuous A2A 的历史和未来必须是相同的物理轨迹定义：相同格式、单位、坐标系、旋转复合、控制器版本、时序和 target 定义。相同维度或相同列名不是证据。
00126 | 
00127 | 每个 continuous channel 至少声明：
00128 | 
00129 | ```json
00130 | {
00131 |   "action_key": "eef_pose_canonical",
00132 |   "source_state_key": "eef_pose_canonical",
00133 |   "kind": "continuous",
00134 |   "dim": 9,
00135 |   "canonical_format": "xyz_rot6d",
00136 |   "source_format": "xyz_rot6d",
00137 |   "target_format": "xyz_rot6d",
00138 |   "source_unit": "meter_unitless",
00139 |   "target_unit": "meter_unitless",
00140 |   "source_frame": "world",
00141 |   "target_frame": "world"
00142 | }
00143 | ```
00144 | 
00145 | contract 还必须绑定 dataset immutable revision/fingerprint、原 schema SHA、canonicalizer name/version/code SHA、controller type/version/scale/control_delta/frame/rotation composition、target definition 和 observation/action time alignment。
00146 | 
00147 | ### 5.1 时间对齐
00148 | 
00149 | 论文定义历史 `a[t-7:t]`、未来 `a[t+1:t+8]`。仓库 loader 的固定窗口是 state `[-7..0]`、action `[0..7]`。两者只有在数据行 `t` 的 action `[0]` 定义为“观察 t 后下一条控制目标”时等价。若 action `[0]` 是同步 `a_t`，预处理必须向后平移，不能让 source/target 重叠一帧。
00150 | 
00151 | ### 5.2 原始 LIBERO 为什么被拒绝
00152 | 
00153 | 原始 LIBERO state 是 absolute measured EEF xyz + absolute rotation-vector + 2D gripper qpos；action 是 dimensionless OSC_POSE delta command + 1D gripper command。二者不在同一空间。
00154 | 
00155 | 即使知道当前 `q[t]`，也只能精确构造第一步 controller goal。后续 action 以每一步真实 measured `q[t+k]` 为参考，受跟踪误差、碰撞、接触和限幅影响；用上一 goal 递推不是数据真值。旋转又必须按矩阵群复合，不能把三个 rotation-vector 分量逐维相加。
00156 | 
00157 | 所以 stock LIBERO 在严格模式会 fail-fast。这是正确性保护，不是可直接训练的 LIBERO adapter。若要使用 LIBERO，必须另行实现：
00158 | 
00159 | 1. 离线读取每个 future action 对应时刻的 measured EEF，生成版本化 absolute controller-goal canonical 列；或改用 actual future pose target。
00160 | 2. gripper 单独作为 binary auxiliary。
00161 | 3. 在线输出 absolute target 时，使用每控制子步最新 measured state 做 inverse-controller；第一版推荐 `n_action_steps=1` receding horizon。
00162 | 4. 将上述 controller commit、scale、frame、旋转左/右乘和时序全部写入 contract。
00163 | 
00164 | 另一条独立路线是 command-history A2A：训练窗口改成过去和未来均为实际下发的 OSC command，在线 buffer 也记录 issued command。它同空间且实现更直接，但语义是 commanded history，不是论文强调的 executed proprio feedback，也不是当前模型输入契约。
00165 |

00254 | 
00255 | ### 7.3 从原始 N1.7 迁移了哪些权重
00256 | 
00257 | 原始 `Gr00tN1d7` 只提供 VLM backbone 和 VLLN allowlist；旧 action encoder、DiT 和 decoder 不会加载到 A2A 头。shape/type/未知 key 会形成明确迁移报告。完整 A2A resume 才恢复 trajectory AE、FlowNet、condition/aux head 与 processor contract。
00258 | 
00259 | ### 7.4 训练噪声
00260 | 
00261 | 默认仅训练时向有效 history 添加 `std=0.02` 噪声；`tau` 始终以 FP32 从连续 Uniform 采样，避免 BF16 把时间量化成 256 个值。默认 inference noise 为 0，所以推理确定性。论文不同噪声消融使用过不同标准差；若复现其多模态附录，需显式建立对应配置和随机 seed，不能把默认 0.02 视为所有论文主实验的统一固定值。

00263 | ## 8. 在线推理
00264 | 
00265 | 推荐客户端直接提供完整实际 history：
00266 | 
00267 | ```python
00268 | observation = {
00269 |     "video": {"front": video_batch},
00270 |     "state": {"eef_pose_canonical": history_batch},  # [B, 8, D_state]
00271 |     "language": {"annotation.human.task_description": language_batch},
00272 | }
00273 | actions, info = policy.get_action(observation)
00274 | ```
00275 | 
00276 | 兼容旧客户端时，每次可发送 `[B,1,D]` 当前 measured state。policy 为每个 batch element 累积实际历史并输出 valid mask：
00277 | 
00278 | - `repeat_first_state`：首帧不足时左侧重复，但重复位 mask=0；模型不会把它当真实历史。
00279 | - `require_full_history`：未满 8 个真实样本直接拒绝。
00280 | - `timestamp` / `state_history_timestamps`：检查严格单调和外部完整历史。
00281 | - `a2a_max_time_gap_s`：拒绝丢帧造成的过长间隔。
00282 | - `policy.reset()`：新 episode、急停、任务切换必须调用。
00283 |

00348 | ## 11. 常见失败与含义
00349 | 
00350 | - `Strict A2A requires explicit a2a_channel_specs`：没有证明历史与未来同物理空间。
00351 | - `Raw LIBERO ... OSC delta commands`：正尝试把原始 LIBERO 绝对 state 与 delta command 直接配对；必须先 canonicalize。
00352 | - `contract does not match expected`：通道顺序、控制器或 dataset provenance 漂移。
00353 | - `requires 8 real history steps`：`require_full_history` 冷启动尚未完成或 valid mask 含 padding。
00354 | - `history and future continuous masks must describe the same channels`：shared encoder 两侧的连续语义不一致。
00355 | - `generation masks must be zero outside future_action_mask`：padding 位置被错误分给 head。
00356 | - `active constant canonical channels`：统计中有零方差有效通道；先检查数据或显式移出 continuous latent。
00357 | - `checkpoint SHA ... does not match`：TensorRT engine 来自不同 A2A 权重，即使模型 shape 一样也不允许加载。
00358 | - `fixed number of Euler steps`：TensorRT 图的步数不可运行时覆盖，需要重新导出。
