00016 | """Single source of truth for the deployment CLIs' shared mode-flag value sets.
00017 | 
00018 | ``scripts/deployment`` is not an importable package, so every value set
00019 | shared across the CLIs lives here and is imported via ``gr00t.*``. A CLI
00020 | never re-authors these strings — it imports the enum or fails on a name
00021 | that does not exist, so cross-file drift is not expressible.
00022 | 
00023 | Each mode flag is one enum here, imported by its CLI. The enums hold the
00024 | legitimate *subset* each tool supports (the tools really do run different
00025 | subsets — that is genuine capability, not duplication):
00026 | 
00027 | - :class:`ExportMode` — the two ``export_mode`` CLIs (``export_onnx_n1d7``,
00028 |   ``build_trt_pipeline``).
00029 | - :class:`VerifyMode` — ``verify_n1d7_trt`` ``--mode``.
00030 | - :class:`BenchmarkMode` — ``benchmark_inference`` ``--trt-mode``.
00031 | - :class:`BuildEngineMode` — ``build_tensorrt_engine`` ``--mode``.
00032 | - :class:`InferenceMode` — ``setup_tensorrt_engines(mode=...)``, shared by the
00033 |   sim-eval rollout ``--trt-mode`` and ``standalone_inference_script``.
00034 | 
00035 | Each member's value equals its name (via :func:`_generate_next_value_`), so
00036 | ``tyro`` keeps the value-form CLI surface unchanged (``--mode full_pipeline``,
00037 | not ``--mode FULL_PIPELINE``) — no CLI/README/docstring edits needed when
00038 | switching from a ``Literal``.
00039 | """

00048 |     """``enum.StrEnum`` stand-in for Python 3.10 (dGPU/Orin).
00049 | 
00050 |     Members are ``str`` subclasses whose value equals their name, so ``==``,
00051 |     ``in``, dict-keying, JSON, f-strings, and ``tyro`` choices all see the bare
00052 |     value. ``__str__`` is restored to ``str``'s so ``str()``/``%s`` yield the
00053 |     value rather than ``ClassName.member``.
00054 |     """
