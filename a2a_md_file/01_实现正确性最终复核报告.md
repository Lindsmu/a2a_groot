## 3. 核心数学逐项核查

### 3.1 同一个 encoder 编码历史与未来

位置：`gr00t/model/gr00t_n1d7_a2a/gr00t_n1d7_a2a.py:460-464,489-490`。

```text
z1 = E_a(future)
z0 = E_a(history)
```

`self.trajectory_encoder` 是同一个模块实例，不是两个独立 encoder。MLP 使用 `ActionTrajectoryEncoder`，DiT 使用 `ActionTrajectoryTokenEncoder`，但各自后端内部都共享同一实例来编码 source/target。

### 3.2 Flow Matching 路径和目标速度

位置：同文件 `:491-505`。

```text
tau ~ Uniform(0,1)
z_tau = (1-tau) z0 + tau z1
v_target = z1 - z0
L_FM = MSE(v_theta(z_tau, tau, c), v_target)
```

实现先用 FP32 采样 `tau`，再转换成 latent dtype，避免 BF16 只有很少离散时间值的问题。MLP latent 的 `tau` 广播为 `[B,1]`；DiT token latent 广播为 `[B,1,1]`。

### 3.3 Autoencoder loss

位置：同文件 `:462-464`。

```text
future_reconstruction = D_a(E_a(future))
L_AE = masked_L1(future_reconstruction, future)
```

mask 只允许 continuous channel 进入共享 latent 和 AE loss。binary/categorical/regression 辅助通道不会污染 continuous latent。

### 3.4 Integration Consistency

位置：同文件 `:507-528`。

```text
z1_hat = Euler(v_theta, z0, condition)
L_IC_latent = L1(z1_hat, z1)
L_IC_action = masked_L1(D_a(z1_hat), future)
L_IC = L_IC_latent + 0.5 * L_IC_action
```

Euler 过程保留梯度，因此 IC loss 可以训练 FlowNet 和相关模块。`euler_integrate` 已泛化到 `[B,D]` 与 `[B,H,C]` 两种 latent 形状。

### 3.5 总损失

配置位置：`gr00t/configs/model/gr00t_n1d7_a2a.py:51-55`；执行位置：action head `:543-559`。

纯 continuous 论文核心路径：

```text
L_total = 1.0 L_FM + 0.5 L_AE + 1.0 L_IC
L_IC = L_IC_latent + 0.5 L_IC_action
```

本项目还提供 `L_aux` 处理 mixed action，这是工程扩展。没有 auxiliary channel 时该项为 0。

## 4. 两种 A2A 后端核查

### 4.1 A2A-MLP

- 轨迹形状：`[B,8,D] -> [B,512]`；
- encoder：3 层 kernel-5 Conv1d，再做 masked temporal pooling；
- velocity field：4 个 AdaLN residual MLP block；
- decoder：4 个 residual MLP block；
- 默认 `a2a_strict_paper_architecture=True` 会检查这些核心结构参数。

该路径是论文核心方法在 GR00T 条件主干上的迁移。

### 4.2 A2A-DiT

- 轨迹形状：`[B,8,D] -> [B,8,C]`；
- token encoder 保留真实时间轴，不把一个全局向量随意 reshape；
- 每个 token 加相对位置和 real/padded validity embedding；
- velocity field 使用 temporal self-attention + AdaLN condition；
- attention 只在 action latent 时间 token 之间发生，VLM condition 经 AdaLN 注入；
- 默认大配置为 `C=256, layers=8, heads=8`；公平 512 元素预算对照使用 `C=64`。

显式 QKV attention 代替 `nn.MultiheadAttention`，避免传统 ONNX exporter 产生不支持的 `_native_multi_head_attention`。对应 ONNX 数值测试已经通过。

## 5. mask、shape 和异常输入核查

action head 在执行公式前检查：

- history/future horizon 必须严格等于配置；
- mask 必须 finite 且为二值；
- 每个 batch sample 至少有一个 continuous channel；
- history 与 future 的 continuous channel support 必须一致；
- continuous、auxiliary、binary、categorical mask 不得重叠；
- 有效 future 位置必须被某个 head 覆盖，padding 位置不得被错误覆盖；
- active history/future 中不能出现 NaN/Inf；
- embodiment id 必须在合法范围。

DiT cold-start 时，无效 history 位置会在输入前和每层 temporal Conv 后再次清零，阻断 padding 值经卷积泄漏；但 token 不被删除，因为相同位置仍要生成未来动作。

## 6. 数据与在线历史核查

### 6.1 训练数据窗口

`A2AShardedSingleStepDataset` 对所有 modality 的 delta index 求严格合法 anchor 交集。训练禁用 padding，避免 Python 负索引从 episode 尾部回绕到开头。

默认窗口：

```text
state/history delta = [-7,-6,-5,-4,-3,-2,-1,0]
action/future delta = [0,1,2,3,4,5,6,7]
```

这里假定数据行 `t` 的 action[0] 表示“观察 t 后的下一控制目标”。如果数据定义为同步 `a_t`，必须在 canonical 预处理时平移，不能让历史和未来重叠。

### 6.2 在线历史

`A2AProprioHistoryBuffer` 只记录真实 proprio/已执行状态，不记录模型预测动作。它验证：

- batch、key、shape、dtype schema 稳定；
- timestamp 严格单调；
- 可选 `max_time_gap_s`；
- episode reset；
- 外部完整 history 与逐帧积累两种入口；
- cold-start valid mask。

`repeat_first_state` 会补齐数值但 mask 仍为 0；`require_full_history` 在 8 个真实样本不足时直接拒绝推理。

## 7. 配置、checkpoint 与部署核查

- `Config.load_dict` 会依据 `model_type` 恢复 `Gr00tN1d7A2AConfig`，不会得到字段看似 A2A、实例仍是原 N1.7 的错误对象；
- 从原始 N1.7 checkpoint 启动时只迁移允许的 VLM 权重，不会误把旧 action head 当作完整 A2A；
- 完整 A2A resume 会验证 MLP/DiT backend、token width、layer/head 数等架构字段；
- MLP checkpoint 不能静默载入 DiT，反向也不能；
- processor resume 允许并验证 A2A horizon、spec、statistics、cold-start 和 contract hash；
- ONNX metadata 绑定 checkpoint、canonical statistics、data contract、ONNX SHA 和 backend；
- TensorRT wrapper 处理 10 输入契约、engine dtype 和动态 shape。

## 8. 仍然存在的边界，不应误写成“全部效果已复现”

### 8.1 真实机器人数据转换仍需用户实现

通用 exporter 只接受已经 canonicalized 的相同物理轨迹列。项目没有自动猜测某个机器人的 state/action 变换，也不会把“维度相等”当作物理一致。

原始 LIBERO 的 absolute EEF state 和 OSC delta action 不在同一空间；当前严格门禁拒绝它是正确行为。要训练 LIBERO，仍需 controller-aware 离线 canonicalizer 和在线 inverse-controller。

### 8.2 尚无真实闭环效果数字

当前没有随代码提供：

- 真实 canonical 训练集；
- 训练完成的 MLP/DiT A2A checkpoint；
- 3 个随机种子的闭环成功率；
- MLP 与 DiT 的显存、延迟、成功率对比；
- 真实 TensorRT GPU engine build/benchmark。

所以可以声称“代码与核心公式正确”，不能声称“GR00T 上已经达到论文成功率”。

### 8.3 论文实验网络并非逐比特复刻

GR00T VLM 取代论文 ResNet18 条件网络；默认示例保留 GR00T 单帧/原视觉 horizon，而论文实验使用 8 帧视觉历史；mixed action、multi-embodiment、ONNX/TensorRT 都是工程扩展。

## 9. 推荐的下一阶段验收

1. 对自己的 canonical 数据做 32～128 个样本 tiny overfit，确认 AE L1、FM、IC 同时下降；
2. 监控 latent per-dimension std、pair distance 分位数和物理单位重建误差；
3. 用相同 base checkpoint、数据、batch、训练步数和 3 个 seed 比较 MLP、DiT-64、DiT-256；
4. 报告 1/2/4/6 Euler steps 的成功率与延迟；
5. 最终以闭环任务成功率选择后端，不只看 validation FM loss。
